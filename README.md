# CarService

Бэкенд информационной системы мультибрендового автосалона на Go. Система построена как два микросервиса с асинхронным обменом через брокер сообщений и синхронным межсервисным вызовом по gRPC.

## Возможности

- Заказы на автомобиль в наличии и на автомобиль с индивидуальной комплектацией
- Конфигуратор: сборка комплектации из совместимых узлов и расчёт итоговой стоимости
- Заявки на тест-драйв
- Ролевой доступ (USER / MANAGER / WAREHOUSE_ADMIN / ADMIN): клиент видит и отменяет только свои заказы, менеджер работает со всеми, склад отвечает за сборку
- Витрина автомобилей в наличии - данные предоставляются складским сервисом по gRPC
- Внутренний складской процесс сборки заказа, запускаемый событиями из сервиса заказов

## Технологии

- Go, Gin
- PostgreSQL (отдельная база на каждый сервис), миграции через golang-migrate
- RabbitMQ - асинхронные события между сервисами
- gRPC + protobuf - синхронные запросы витрины автомобилей
- JWT - аутентификация и авторизация
- Docker / docker-compose


Запуск всех сервисов:

```
make up      # docker compose up -d --build
```

Остановка - `make down`. Миграции применяются автоматически при старте, склад засеивается тестовыми автомобилями.

## Основные эндпоинты

OrderService:

- `POST /auth/login`
- `GET  /api/v1/cars`, `GET /api/v1/cars/{id}` - автомобили в наличии (через gRPC к складу)
- `GET/POST /api/v1/orders/in-stock` и действия по заказу (`/approve`, `/pay`, `/cancel` и др.)
- `GET/POST /api/v1/orders/custom`
- `GET/POST /api/v1/test-drives`
- `/api/v1/car-models`, `/api/v1/details`

StorageService:

- `/api/v1/assembly-orders` - заказы на сборку (WAREHOUSE_ADMIN / ADMIN)
- gRPC-сервис `CarStock` на `:9091`
